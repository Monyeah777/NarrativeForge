# 45 · 执行遥测规范（真实转录/E3 补测底座）

> ⛔ 操作指令：执行留痕格式与采集器口径（阅读即执行）。
> 最后更新：2026-09-14

## 目的

动态可执行保真缺「真实 AI 执行转录」——封闭期不引外部实测（E3 作者触发）。在等真实转录前，先立**执行遥测格式与落盘面**：`nf assemble --trace <file.json>` 把每次计划/澄清/验收运行留痕，将来 E3 真实转录按同一结构回填即可做对比。

## 格式（nf assemble --trace）

```json
{
  "tool": "nf assemble",
  "phase": "plan | clarify | check",
  "requirement": "<用户一句话>",
  "status": "preset | custom",
  "matched": true,
  "package": "西幻生存领域包",
  "pipeline": "P03",
  "allowed_modules": 44,
  "ok": true,
  "issues": [],
  "stats": {"segments": 8}
}
```

## 采集纪律

## 对外消费：semconv 映射（`nf telemetry`）

上面的 trace 记录是 NF 自定 JSON；对外消费走映射，**不改 trace 格式本身**：

```bash
python scripts/nf.py telemetry <trace.json>          # 打印 semconv 属性视图
python scripts/nf.py telemetry <trace.json> --otlp   # OTLP 形状（resourceSpans → scopeSpans → spans）
```

映射（属性名照抄 OTel GenAI 语义约定，不做同义改写）：`gen_ai.operation.name=execute_tool`、
`gen_ai.tool.name=nf.<命令>`、`gen_ai.tool.call.id`（由记录内容派生，可复现）、
`gen_ai.tool.call.arguments`（requirement/phase/status）、`gen_ai.tool.call.result`
（matched/package/pipeline/ok/issues…）、`gen_ai.agent.name`、`gen_ai.conversation.id`。

**边界（不含糊）**：只对齐**属性命名与 OTLP 形状**，不实现 protobuf 编码、不提供导出端点
——「能被 collector 适配」≠「已宣称 OTLP 传输兼容」；schema_url 未填（官方 semconv 站点
该字段尚标 TODO，不杜撰）。

- phase=plan/clarify：需求→计划/澄清留痕；phase=check：成品验收留痕（issues/stats）。
- 时间戳不写入（确定性优先，与 golden 同纪律）；需时序时由采集方外套 UTC 字段。
- 真实转录（AI 执行回合/输出文本）到位后：同一结构增 phase=execution 与 transcript 字段，按 E3 一次性补测回填。
