# 实验提案：状态前置 vs 状态后置（T3 · 设计件）

> 性质：**提案**（可选执行）。依据的相邻观察：`arXiv:2609.02702（2026-09-02，预印本）`报道「条件先行优于条件后置」；
> 本提案只把它当作**可检验的外部现象**，在 NF 的可复现场景里做对照——**不假定结论成立**。
> 执行状态：未执行（本包只交提案；执行列 backlog）

## 1. 目的

在一个可复现的 NF 长内容场景中，对照「状态 / 对账块置于资料**之前**」（条件先行）与
「后置 / 省略」对产出的差别。目的是**取得自己的数据**，而不是复述外部结论。

## 2. 设计

| 项 | 设定 |
|---|---|
| 场景 | 选取仓库最近可复现的装配场景（如：取一条既有管线 + 固定模块集，需求文本固定） |
| 素材 | 固定不变（同一模块集 / 同一资产包 / 同一需求串） |
| 条件 A | **前置**：状态块（如世界模型摘要 + 回合状态头 + 关键设定表）置于资料**之前** |
| 条件 B | **后置**：同一状态块置于资料**之后** |
| 对照 C（可选） | **省略**：不给状态块，只给资料 |
| 控制 | 同模型、同参数、同温度；每条件 **≥3 轮**；记录轮次与耗时 |
| 通道 | 有模型通道则执行；无通道 → 只交提案（本包按此处理） |

## 3. 指标（都用 NF 可测项定义）

1. **关键设定保持率**：产出中命中「设定表」条目的比例（可脚本统计）；
2. **重读引导效果**：产出里出现状态块中术语/编号的次数与位置（可脚本统计）；
3. **人工质检问题数**：按 `docs/st-quality-checklist.md` 勾选，记未通过条数；
4. **机器可判项**：`nf st-validate`（可自动化项）与 `nf assemble --check` 的 fail/warn 数。

## 4. 预期输出格式

- 每轮一条记录：`{条件, 轮次, 模型, 参数, 指标1..4, 原始输出路径}`；
- 汇总表：三条件 × 指标的均值/极差；
- **负结果同样记录**；样本不美化、不剔除不利轮次。

## 5. 归档与时序

- 若执行：记录落 `results/`（按仓库既有惯例命名）+ 原始输出存档（同目录）；
- 若未执行：保持本提案状态，标 backlog（本包即此）；
- 提案本身不改任何协议语义与既有行为（红线 1 遵守）。
