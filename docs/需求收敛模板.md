# 需求收敛模板（41 波C C6 · 上游衔接）

> 定位：把真实需求从模糊叙述收敛为**可直接生成 steelman / audit 工作单的澄清稿**（上游衔接，补 steelman/audit 之上游）。任一协作 agent 拿到回填稿即可走自动流转链，条目自包含。

## 一、澄清稿模板（回填即用）

```text
需求澄清稿
1. 一句话需求：<把用户原话压缩为一句可验收陈述>
2. 背景与痛点：<为什么现在做；现有哪一环断了>
3. 谁消费（决策人 / 外部方）：<作者 / 外部验证方 / agent 用户；无消费方即未成熟>
4. 范围边界（做 / 不做）：<明确纳入项与排除项，防止范围蔓延>
5. 验收标准（可测断言）：<命令 + 期望输出 / 单测断言；无法断言 = 未收敛>
6. 风险与未知（低置信度项）：<3-7 项，标注影响>
7. 涉及协议 / 文件：<01/02/03/04/… 或 desktop/src/core/… 清单>
8. 素材引用：<实测回执 / 外部文档 / 编号条目；无素材如实声明>
```

## 二、自动流转链（回填稿 → steelman → audit → 草案留档）

1. 澄清稿落 `docs/需求澄清_<slug>.md`（按上文模板回填）。
2. 生成 steelman 工作单：
   `python scripts/nf.py design steelman init "<一句话需求>" --context "C6:<slug>; 澄清稿:docs/需求澄清_<slug>.md" --out steelman_<slug>.md`
3. 生成 audit 档案（可选 full）：
   `python scripts/nf.py design audit init "<审计问题>" --target "<对象>" --mode full --out audit_<slug>.md`
4. 草案留档：决策/方案正文放 `docs/` 或随波落库；`nf design steelman ls` / `audit ls` 可回溯索引。

## 三、首例（NF-FIELD-001 · Y5 回填）

首例 = 把「Y5 外部复测结果回填 `docs_external-validation*` 对账表」作为真实需求走完整链。当前阻塞：**NF-FIELD-001 实测回执原件（「外形完整、执行失范」黄金反例）不在仓库**——作者提供原件后按上文模板回填 → 生成工作单 → 草案留档 → 回填对账表 + 反例入 tests/fixtures（D7）。素材未到前不虚构结论。
