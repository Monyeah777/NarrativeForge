# 44 · AI 通道内容规范（实质内容面 · 标准资源 + 内容工具）

> ⛔ 操作指令：AI 通道取用规则（先读后写 / URI 约定 / 取用纪律，阅读即执行）。
> 最后更新：2026-09-09
> **目的**：AI 通道（`nf serve` + 装配引导）不只是“框架/目录”——任何 AI 都能取到仓库**实质内容**（模块正文 / 管线正文 / 资产正文），并按“先读后写、禁止凭记忆”的取用纪律装配。

## 1. 表面与 URI 约定

| 取用面 | 内容 | 示例 |
|---|---|---|
| `resources/read` | 快照资源（nf://P90/…） | `nf://P90/P10/…` |
| `resources/read`（44 深化） | 仓库内容资源（nf://repo/…） | `nf://repo/module/M90` / `nf://repo/pipeline/P90` / `nf://repo/asset/官方/TECH_RULES` |
| `tools/call`（44） | 内容工具（语义化取用） | `module_read {module_id}` / `pipeline_read {pipeline}` / `asset_get {key, package?}` |
| `tools/call`（41 C7） | 检索工具 | `library_search` / `registry_query` / `pipeline_ls` / `spec_ls` |
| `prompts/get` | 装配引导 | `assemble_guide` |

`resources/list` 只回纯元数据（无 text，G2）；正文一律经 `resources/read` 或内容工具取回。

## 2. 覆盖与解析口径

- 模块：44 件模块文档全量可寻址（`04_模块库` + `community/*/modules`）——**含无机读块的存量内容模块**（按标题/文件名 id 解析，`has_machine_contract` 如实标注）；同号限定（如 通用:M10 / 生存:M10）须用全限定 id。
- 管线：8 条（03 官方 + community pipelines），按 Pxx 或仓库相对路径解析，路径白名单防越界。
- 资产：community 包 assets + 05 用户自定义，**多键登记**（文件名令牌 ∪ 正文键声明 `` `KEY` `` / `` "KEY": `` / `` ## KEY ``），每键独立资源条目 + 可选包解析。
- 未知目标 → `-32602` 参数级拒绝（消息带修复指引）；全部只读、无写面。

## 3. 取用纪律（硬断言口径）

- 装配输出凡涉及模块职责/事件/资产内容，必须先经内容工具或 `resources/read` 读取真实正文——不得凭记忆/印象写未读取内容（对齐 execution_drill R1-R4）。
- 资产/模块/管线引用如实标注来源（文件路径/§/行号）；编造编号、职责错位、无引用决策均属失范（对应 drill 失范类别）。

## 4. 与既有设施的关系

- 数据源仍为仓库只读扫描，不与 C2 只读安全层冲突；资源/工具/引导三面同源同一套解析（无第二份真值）。
- 外部标准客户端实测仍按 STRATEGY 封闭期冻结（E3 口径），本规范为内部可执行面。
