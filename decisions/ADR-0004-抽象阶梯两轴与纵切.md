## 背景

NF 已有四套「层」的词汇：L0–L3（依赖治理编号，见 `docs/L3_FROZEN.md`）、P00–P80（管线层位）、
`mount_layers`（模块挂载层）、标准目录 layer（data/eng/form/gov/iface）。四套各有其义，但
「谁在动」（终端、AI、外部工具）与「被加工的物」（协议、资产）此前混在同一根梯子上，于是出现
「终端在最底、AI 在顶」这类把**角色**当**层**的错位。端壳退役是这条缺口的实证：一个角色被当成
一层，整层退役时能力无处安放，只能事后补判据兜住（check39）。

## 决策

抽象阶梯采用**两轴 + 纵切**，且**不复用任何既有编号**（不叫第五套「层」）：

- **抽象轴四阶**：契约 → 资产 → 引擎 → 出口；越往下越稳定越贵改，依赖只许向下；
- **入口面**：人机 / AI 装配线 / MCP / 图书馆取件——只登记角色，`is_source_of_truth` 恒为 false；
- **验证纵切**：门禁与证据（verify / conformance / audit / receipts / attest / provenance）切过四阶，
  不是层，故不参与归属互斥。

每阶登记四件事：真源面、接口面（跨阶唯一可依赖）、实现面（可替换）、变更档与既有判据。
真源 = `protocol/LAYERS.json`；判据 = `core/layer_model.py` 的 L1–L10，接线进 check27 的 R7；
形状类断言（声明件在场 / 生成区在场 / 无绝对路径）按 ADR-0003 进 `protocol/assertions.json`；
不新增 check 序号（遵 ADR-0002）。一阶退役走三步规程（能力重分派 → 入口补齐 → 判据改判 + 记录）。

## 后果

好处：① 「改实现」与「改接口」第一次可分——跨阶只许依赖接口面，重构因此有安全边界；
② 角色与物分离后，入口可被整体替换（端壳 → 终端即一次替换）而真源不动；
③ `docs/layers.md` 的阶梯表是生成投影，不再手写漂移（L10 断言逐字一致）。
代价：① 每加一件机读件都要登记进 `protocol/LAYERS.json` 的某一阶，否则 L1/L2 会报；
② 阶归属判据**有界**——只判阶梯自己声明的真源面，不给全树逐文件贴标签（那属另一个量级的承诺）。
