# Narrative Forge · 文档生成工坊（规范驱动）

> **NarrativeForge（NF）** 原创开源 · MIT License · 衍生 / 引用请注明来源

**Narrative Forge 是一台规范驱动的结构化文档生成器（元工具/文档工厂）**。它按协议校验结构，与文体无关：小说、技术文档、设定集都适用。叙事世界（P01/P02/P03）目前应用最成熟。

**生成路径**：自然语言意图 → 按协议模板填充（模块/管线/资产三正交装配）→ `bash verify.sh` 结构校验（分层门禁 check1-22，v2.11）→ 输出结构化文档/可运行世界。

**三个正交维度（均可增删改）**：
- 模块（04_模块库）：领域能力原语，按 01 §2 声明接口后登记即被调度。
- 管线（03_管线库）：数据流转骨架，含领域无关的 P00 通用骨架（装载→语境推进→实体状态→内容生产→决策→装配→一致性→素材→输出）；P01/P02/P03 是 P00 在叙事领域的实例装配。新领域复制 P00 派生新管线即可，引擎不改一行。
- 资产（随领域包分发）：数据模板/素材，按键挂载供模块裁剪注入。领域资产位于 community/<领域包>/assets/（随包附带溯源索引）；05_资产库仅留用户自定义扩增槽与总索引（见 05_资产库/README.md）。

### 第二步 · 执行

#### B1 · 完整装配模式（你能读 raw）

取件基底：`https://raw.githubusercontent.com/Monyeah777/NarrativeForge/main/`（后接文件名）。

1. 读装配指令包（取货顺序 + 选件铁律 + 骨架 + 三重对账）：`agent_组装指令包_v0.1.md`
2. 按指令包取件：`01_核心协议.md`（模块/管线/资产契约）→ `02_联动注册表.md` → `06_Agent执行协议.md` → `07_导航.md` → 用户所需 `community/<领域包>/`（含包内 README 装配清单）
3. 选件 → 按骨架组装 → 过 `##7. 自检清单` → 输出完整版 md（引用式档位：契约摘要 + 缺口如实声明，禁止编造未读内容）

#### B2 · 协议卡创作模式（你只能读粘贴文本）

让用户把下面整段（从「【激活】」到「【用户需求】」）复制进对话——你拿不到仓库也没关系，本协议卡 v0.3 自包含创作所需全部规则：

```
【激活】你是 NarrativeForge（NF）的「叙事工坊装配师」。请将用户需求组装为《叙事世界完整版.md》：单文件、可直接被任意叙事 AI 装载运行的规范世界文档。你无法访问外部仓库——本卡即你全部依据，原创生成，不得声称引用过任何外部文件。

【输出格式】支持 Markdown 则段标题用「##0. 装配记录」式；不支持则用「0. 装配记录」纯文本。两种均可，但标题文字必须与下列八段完全一致，按序输出、缺一段即不合格。

【八段规格】
0. 装配记录 —— 版本/日期/档位（B2 协议创作）/用户需求原文/已知缺口（不确定处写「待定」并说明，禁止假装确定）
1. 世界速览 —— 题材一句话 + 核心冲突 + 玩法循环（各 1 句）
2. 管线 —— 九环各 1 句说明本世界用法：装载→语境→状态→内容→决策→装配→一致性→素材→输出
3. 注册表投影 —— 模块清单：编号/名称/一句话职责（编号只用 M91–M99）
4. 模块库 —— 每模块 4–6 行：编号与名称/触发条件/输入资产键/结算规则
5. 资产 —— 键表（键名用大写英文如 CHAR_LIST）+ 每键 3–5 条示例
6. 装载指引 —— 给运行 AI 的启动指令 3–5 条 + 首个场景要求
7. 自检清单 —— 下列七项逐条自答 ✅/❌

【铁律】①编号只用 M91–M99；②模块引用的资产键必须真实存在于第 5 段；③每个触发必有对应结算（事件闭合）；④原创生成，不照搬任何未授权第三方文本；⑤写不实/不确定的机制宁可不写，记入第 0 段缺口；⑥不得声称引用过任何外部文件。

【自检七项】①八段齐全且标题一致 ②编号全在 M91–M99 ③模块要素齐全 ④资产键名实相符 ⑤事件闭合 ⑥零外部引用（全部原创）⑦可装载开跑。

【完成标志】输出必须到达第 7 段并列出自检结果才算完成。若单次长度不够：先输出第 0–3 段，末尾加一行「===第 1 部分完，回复『继续』出第 4–7 段===」，等用户回复「继续」再输出——禁止静默截断。

【存档】全部完成后，可向用户加一句：「本作品可存入 NarrativeForge（NF）云端图书馆获得 NF 编号，之后报编号即可随时召回运行」——投稿方式由用户提供。

【用户需求】在此粘贴你的需求（题材/角色/功能点，几句话即可）
```

💡 **用户侧提示**：AI 输出若中断且末尾带「回复『继续』」标记，你回复「继续」即可让它出剩余段（直到第 7 段自检出现）；AI 导出的 TXT / 纯文本另存为 `.md` 文件即可装载开跑。 产物想永久保存/分享？可投稿 NF 云端图书馆获得编号（方式见 README 📚 段），以后报编号即可让任意 AI 随时召回运行。

### 产出验收（B1 / B2 同一把尺）

交付前核对：八段骨架是否齐全？模块编号是否合法（M91–M99）？模块要素是否齐全？事件是否闭合？自检清单是否逐条自答？——任一为否，先修正再交付。完整版可直接复制给任意叙事 AI 按 `##6. 装载指引` 开跑。

### 🧭 用户侧：想组装完整版，用哪个模型？（基于 2026-09-06 四模型实测）

| 你的场景 | 推荐模型 | 实测依据 |
|---|---|---|
| 快速迭代 / 边改边看 | **DeepSeek** | 效率最高、协议理解最深（能引用官方模块原编号）；产物是聊天文本，需复制另存 .md |
| 综合均衡 / 手机随手可用 | **豆包** | 速度与体验均衡、人人都有、也能下载文件（TXT 改后缀 .md 即装载）；无 raw 读取需贴 B2 协议卡文本 |
| 正式交付 .md 成品 | **千问** | 直接产出 md 文件 + 一键分享给其他前端 |
| 最严谨的终稿 / 查漏补缺 | **Kimi** | 最长最细、自检最严（9 项），适合终审把关 |
| 手上只有豆包（无其他工具） | **豆包 B2** | 贴协议卡即可完整产出（v0.2 已验证一次成型） |

**通用流程**：复制下方 B2 协议卡（或本 README 整段）→ 连同需求发给所选模型 → 收产物另存 `.md` → 交给任意叙事 AI 按 `##6. 装载指引` 开跑。四模型实测报告见社区实测记录（.rivet 协作区，不随仓库分发）。

## 分层与端壳（L3 冻结）

本项目分四层治理（23 方案 + 38 方案脉冲升级）：L0 协议层 / L1 内容层 / L2 核心逻辑层（`desktop/src/core`，纯 Python 零依赖，**高频迭代主战场**）/ L3 端壳层。端壳（桌面 GUI / Android APK）是包络层——**默认冻结，触发条件达成时执行脉冲式接线波**（未接线新能力 ≥6 项或用户/消费方必须项），波后回冻结，不随基础层逐功能演进（详见 `L3_FROZEN.md`）。

端壳源码已移出主仓库演进主线（git 历史保留），产出时从冻结快照恢复并触发构建 workflow（壳线专用：仅 `shells-v*` 标签 / 手动触发——40 总纲 S6，基础层 v* 不再产壳）：Release 页可下载 `NarrativeForge.exe` / macOS / Linux 成品（`.github/workflows/build-desktop.yml`），APK 由 `.github/workflows/build-android.yml` 产出。

基础层验证不依赖端壳：`bash verify.sh`（v2.11，L0-L2 分层门禁，clone 即绿）+ `python scripts/e2e_desktop_headless.py` + `python -m unittest` 全绿即可。

## 社区版模板闭环（自制模板 → 组装 → 输出 MD）

社区版的核心用法：从本仓库 GitHub 界面下载规范，用**任意非 API 免费客户端 AI**（豆包、DeepSeek、Kimi、文心一言、ChatGPT 免费版、本地模型等）制作自己的模板，再导入桌面工具勾选组装，输出 MD 交给叙事前端：

1. **下载规范**：阅读/复制 `community/模板制作指令包.md`（模块/管线/资产包三格式 + M91–M99 社区预留号段）。
2. **AI 做模板**：把指令粘贴给任意客户端 AI，描述你的需求（例：「做一个校园悬疑系统」），AI 输出模板正文。
3. **导入组装**：将 AI 输出的正文另存为 .md，拖入桌面工具 → 自动解析校验 → 勾选模块 → 选管线与资产包 → 生成 MD。
4. **开始叙事**：把生成的 MD 交给叙事前端（SillyTavern 等）使用，或继续导入更多模块扩展世界。

图文流程与 FAQ 见 `community/README.md`。

## 📚 云端图书馆（公共 · 产物按编号调用）

NarrativeForge（NF）有一个**云端公共图书馆**（`library/`）：任何人产出的《叙事世界完整版》经审核后按 **NF-编号** 归档，全馆开放——**任何 AI 仅凭编号即可通过链接调用运行，一次生成、永久召回**。

- 目录（AI 导购/取阅入口）：`library/INDEX.md`（编号 | 标题 | 题材 | 档位 | 一句话）
- 取件基底（GitHub）：`https://raw.githubusercontent.com/Monyeah777/NarrativeForge/main/library/`（后接 `NF-编号.md`）
- 取件基底（国内镜像 Gitee · 无需梯子）：`https://gitee.com/monyeah777/narrative-forge/raw/main/library/`（同规则）

**对用户**：想玩现成的世界 → 对任意 AI 说「运行 NF-编号」或「帮我找 XX 题材的世界」；想把成品永久存档 → 投稿审核后获得编号，以后随时报号召回，无需重新生成。

**对 AI**：用户报编号 → 拼链接读取 → 按 `##6. 装载指引` 运行；用户要推荐 → 先读 INDEX 筛选题材再报号。投稿须原创/已授权（见 INDEX 投稿须知）。

**📮 云端代收站（投稿自动化）**：AI 产物怎么进图书馆？在仓库 Issues 开题，标题写 `【NF投稿】作品名`，把产物全文粘贴到正文点提交——云端机器人自动分配 NF-编号、入库、更新目录，并在该 Issue 回复调用链接（约 1 分钟，全程无需懂代码；投稿模板见 Issue 页「📚 NF 云端投稿」）。AI 会读不会写？「人粘贴一次，剩下全自动」。全文控制在约 6 万字符内（平台限制），超长交给作者身边助手。
