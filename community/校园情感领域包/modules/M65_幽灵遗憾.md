# 模块 M65 · 幽灵遗憾

> 类别：情感｜来源：校园｜挂载点：P60 长期演变（active）｜依赖：M41、M40｜发布：`ghost_event`

## 1. 职责

管理**遗憾系统**（REGRET_LIBRARY）：把未完成的告白、错过的回应、没说出口的话沉淀为"幽灵"，在剧情窗口期显形，成为长线情感叙事的暗流。遗憾只在事件:M22 允许的窗口内显形。

## 2. 遗憾库（REGRET_LIBRARY，6 条基线）

```yaml
regret_library:
  R1 未寄出的信:     写了没寄（触发自 M55 情书中断）
  R2 迟到的回应:     回应到达时对方已离开（毕业/转学/死亡）
  R3 没说出口的话:   告白窗口关闭前退缩（M41 判定失败）
  R4 误会的代价:     误会未澄清导致的分离（M55 冒名/误放）
  R5 被抢走的人:     情敌抢先告白成功（M43 结果分支）
  R6 永别的省略号:   重要 NPC 死亡时未了结的关系（订阅 death_trigger/chaos_event）
```

## 3. 遗憾生命周期

```yaml
ghost_lifecycle:
  种子:   情感事件未闭环 → 生成遗憾种子 {type, target, weight, tick}
  沉淀:   种子随 tick 沉入 NPCState/关系史底层（不主动呈现）
  显形窗口: 事件:M22 指定时机（雨天/毕业/旧物/祭日等）→ 允许 ghost_event 浮出
  显形规则: 遵守写作 DNA 输出约束（物件意象承载，情感永不直说）
  闭环:   玩家在窗口期做出回应 → 遗憾消散（转化为关系深度/记忆）
  未闭环: 窗口关闭 → 遗憾加深（weight+），等待下一次窗口或永久封存
```

## 4. 事件契约
> 跨包事件（death_trigger/chaos_event）经官方核心中介事件:M22 事件总线登记为「事件桥」订阅（R1），非直接模块互引。
```yaml
subscribe:
  death_trigger:       # 经事件桥（西幻包发布）→ R6 永别遗憾
  romance_state_change: # M41 → R2/R3 错过类遗憾
  chaos_event:         # 经事件桥（西幻包发布）→ 突发事件中断关系
  narrative_event:     # 事件:M22 → 叙事窗口开启检查
publish: ghost_event
  payload: {ghost_id, regret_type, target_npc, window, weight, tick}
  subscribers: [事件:M22, M80]
```

## 5. 违例与边界

- 遗憾显形窗口内若玩家无操作，不允许自动替玩家做出选择。
- 幽灵不驱动 NPC 行为（那是情感:M22 的职责），只提供叙事素材。
- 记忆读取（v0.5.0 T3 只读声明）：M65 经 M00 数据槽**只读**接口消费三层记忆中的
  `episodic`（关系史/事件史，判断遗憾窗口与沉淀基线）与 `semantic`（长期设定，辅助
  遗憾闭环转化）；只读不写（I4）—— 遗憾写入/加深一律经发布 `ghost_event` 或自身
  声明写槽，**不得直写他模块 memory 字段**。
- 遗憾内容在显形前属隐藏域（M23 裁剪）。
