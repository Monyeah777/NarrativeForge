# 模块 M58 · 电话通讯
> 类别：情感｜来源：校园｜挂载点：P50 交互执行（active，社交结算段）｜依赖：M00、M40、事件:M22｜发布：`phone_call_event`

## 1. 职责

承载校园社交的**电话通讯流**（资产 PHONE_CALL）：回合内按好感度（M40）概率生成 NPC 来电（`affinity_probability` 随好感升高），写入 `player.social.phone_log`。来电是夜间/放学窗口的深度互动通道：接听 → 好感度正向结算（M40）并可能触发事件；拒接/未接 → 沉淀 ghost 素材（M65），制造错过与遗憾。

## 2. 协议声明（01 §1 模块协议）

```yaml
Module:
  id: M58
  name: 电话通讯
  layer: P50
  inputs: [M00 数据槽, M40 关系深度, 情感:M22 冲动结果]
  outputs: [player.social.phone_log, events.pending(来电触发点)]
  events:
    publish: [phone_call_event]       # 来电产生/来电触发点
    subscribe: [quest_state, npc_action, relationship_change]
  core:
    assets: [PHONE_CALL]              # I4：仅经 asset_* 五接口访问，禁止直读
    logic:
      scan_calls: 回合内遍历 NPC → asset_match(PHONE_CALL，按好感度概率) → 入 phone_log；接听分支结算好感/触发事件；拒接分支沉淀 ghost 素材
  replaceable: true
```

## 3. 触发时机

P50 层**社交结算段**（与 M57/M59 同段依序执行）：位于任务推进之后、P60 演变之前，由 M50 按注册表顺序调度调用 `scan_calls`（见 assets/附_社交系统触发联动.md §12.5）。夜/放学窗口来电密度更高（校园作息，见 README §4 四拍节拍）。

## 4. 核心逻辑（scan_calls，与 assets/附_社交系统触发联动.md §12.5 一致）

```python
def scan_calls(state):               # M58
    for npc in state.characters:
        if asset_match("PHONE_CALL", npc=npc, events=state.events, affinity=state.player.affinity[npc.id]):
            call = asset_roll("PHONE_CALL", npc=npc, state=state)
            if call.affinity_probability and roll_probability(call.affinity_probability):
                state.player.social.phone_log.append(call)        # 来电
                if call.trigger_event:
                    state.events.pending.append(call.trigger_event)  # 来电触发事件
            # 拒接/未接 → 沉淀 ghost 素材（M65 结算）
```

> 联动对照（源文 §12.6 矩阵编号为源切片残留，实际对象）：来电触发点 → 事件:M22；接听好感增减 → M40；拒接/未接遗憾 → M65（R1 事件桥）。

```yaml
  npc_action:           # 情感:M22 冲动行为 → 深夜来电语境生成

```

## 6. 违例与边界

- 来电是否接听由玩家决定；模块不得替玩家自动接听/拒接。
- 来电文本受写作 DNA（对话极简、带潜台词）约束；不得泄漏系统真知（M23 认知边界）。
- 三冲动不驱动告白/交往类来电内容（v0.7.12 红线）；恋爱对象专属深夜来电归 M41 内容管。
- 拒接/未接不自动产生惩罚性叙事，只沉淀 ghost 素材供 M65 在窗口期使用。
