# 模块 M57 · 朋友圈动态
> 类别：情感｜来源：校园｜挂载点：P50 交互执行（active，社交结算段）｜依赖：M00、M40、事件:M22｜发布：`social_feed_event`

## 1. 职责

承载校园社交的**朋友圈动态流**（资产 SOCIAL_FEED / FORUM_POSTS）：回合内扫描各 NPC 的动态/论坛帖，按主角与该 NPC 的好感度（M40）决定可见性，推入 `player.social.feed_visible`。动态可作三类用途：①叙事素材（交事件:M22 编排）；②事件触发点（`feed.trigger_event` → 事件 pending 队列）；③隐藏线索埋放通道（`clue_trail` → `hidden_events.clue_progress`，经 M23 认知边界裁剪后呈现）。

## 2. 协议声明（01 §1 模块协议）

```yaml
Module:
  id: M57
  name: 朋友圈动态
  layer: P50
  inputs: [M00 数据槽, M40 关系深度, 情感:M22 冲动结果, 事件:M22 任务进展]
  outputs: [player.social.feed_visible, events.pending(触发点), hidden_events.clue_progress]
  events:
    publish: [social_feed_event]      # 动态流就绪/动态触发点产生
    subscribe: [quest_state, npc_action, relationship_change]
  core:
    assets: [SOCIAL_FEED, FORUM_POSTS]   # I4：仅经 asset_* 五接口访问，禁止直读
    logic:
      scan_feeds: 回合内遍历 NPC → asset_match(SOCIAL_FEED/FORUM_POSTS，按好感度可见) → 入 feed_visible；trigger_event 入事件 pending；clue_trail 推进 hidden_events
  replaceable: true
```

## 3. 触发时机

P50 层**社交结算段**：位于任务推进（事件:M22/M06 回合结算，源文 §12.5 所称 M22.advance_quests 之后）与 P60 演变之前，由 M50 按注册表顺序调度调用 `scan_feeds`（同段依序含 M58.scan_calls / M59.scan_group_chats，见 assets/附_社交系统触发联动.md §12.5）。

## 4. 核心逻辑（scan_feeds，与 assets/附_社交系统触发联动.md §12.5 一致）

```python
def scan_feeds(state):               # M57
    for npc in state.characters:
        if asset_match("SOCIAL_FEED", npc=npc, events=state.events, affinity=state.player.affinity[npc.id]):
            feed = asset_roll("SOCIAL_FEED", npc=npc, state=state)
            state.player.social.feed_visible.append(feed)
            if feed.trigger_event:
                state.events.pending.append(feed.trigger_event)   # 动态作事件触发点
            if feed.clue_trail:
                state.hidden_events.clue_progress[npc.id] += 1    # 线索埋放
```

> 联动对照（源文 §12.6 矩阵编号 M30/M34/M42/M60 等为源文切片残留，无模块文件）：动态触发点 → 事件:M22 pending 队列；话题/素材池 → 资产键（FORUM_POSTS / GOSSIP_TOPICS）；文本表面反应 → 写作 DNA（assets/WRITING_STYLE.md）经 M80 输出；长期演变入 evolution_log → P60 层 M40/M65 结算。

## 5. 事件契约

```yaml
publish: social_feed_event
  payload: {feed_id, npc_id, visibility, trigger_event?, clue_trail?}
  subscribers: [事件:M22]       # 动态内容作叙事素材/事件触发点
subscribe:
  quest_state:          # M06 任务进展 → 重扫动态（动态内容随任务状态自然刷新）
  npc_action:           # 情感:M22 冲动行为 → 生成对应表层动态
  relationship_change:  # M40 好感度档位变化 → 动态可见性重算
```

## 6. 违例与边界

- 动态仅呈现**表层行为**，不得泄漏系统真知（M23 认知边界：事实快照 → 裁剪 → 渲染 → 锚点回验）。
- 三冲动（情感:M22）只驱动动态内容语境，不得代推动态发布主体的关系推进（v0.7.12 红线）。
- 玩家自身动态由玩家行为产生，模块不得替玩家伪造发布。
- 玩家无视动态 → 沉淀 ghost 素材，由 M65 结算（R1 事件桥登记，非直接模块互引）。
