# 模块 M40 · 关系深度

> 类别：情感｜来源：校园｜挂载点：P40 行为决策（active）｜依赖：M00、M13｜发布：`relationship_change`

## 1. 职责

维护主角与每个 NPC 的**关系深度**（INTERACTION_DEPTH 模型），是情感系统的地基。所有关系数值由本模块唯一结算，其他模块只读或请求变更。

## 2. 关系深度模型

```yaml
INTERACTION_DEPTH:
  深度轴: depth (0-100)        # 关系的亲密度总量
  认知轴: cognition (0-100)    # 对彼此的了解程度
  频率效应: 互动频率提升认知轴（见得多→更了解）
  质量效应: 互动质量提升深度下限线（高质量事件抬高底线）
  破坏效应: 冲突/背叛可能击穿下限线 → 触发关系事件（relationship_change 负向）
```

## 3. 结算流程

```yaml
on_interaction(event, npc):     # 订阅 M13 interaction_update / npc_action
  1. 分类事件: 日常/高质量/破坏性（M13 给出 type 标签）
  2. 日常 → cognition +Δc（小幅）
  3. 高质量 → depth 下限线 +Δd，depth 向新下限靠拢
  4. 破坏性 → depth 直减；若跌破当前下限线 → 触发关系事件并重设下限
  5. 写回 NPCState.relation.depth/cognition/history
  6. 若 depth 越档（见 M41 阶段阈值）→ 发布 relationship_change
```

## 4. 事件契约

```yaml
subscribe:
  tick_day:           # 每日衰减/回忆沉淀结算（微量，避免数值膨胀）
  npc_action:         # 情感:M22 冲动行为 → 计入互动质量
  interaction_update: # M13 普通互动
publish: relationship_change
  payload: {npc_id, depth, cognition, delta, reason, tick}
  subscribers: [M41, M43, M55, 事件:M22]
```

## 5. 违例与边界

- 深度为 0-100 软上限，可越限但超限部分标记 `over`，不参与阶段判定。
- 关系历史（history）只增不改；回档由 M50 快照统一处理。
- 禁止其他模块直接写 NPCState.relation——一律走 M40 接口。
