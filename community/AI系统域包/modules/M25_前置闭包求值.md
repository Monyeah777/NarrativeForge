> 类别：AI系统｜来源：社区（AI系统域包自带，类内段）｜挂载点：P40 行为决策（active，default）｜依赖：M00、M50｜发布：concept_closure_ready、prereq_missing｜状态：active
> 用途：读概念图资产 `CONCEPT_GRAPH` → 解析检索词（条目键 / 别名 / 概念名）→ 对目标概念算**前置闭包**与**缺失清单**（`closure(c)` / `missing(c, L)`），把结果写入 `PrereqState` 数据槽并发布事件；是「AI 系统域」相对官方核心的增值位——官方核心管世界知识条目（M20）、可见域裁剪（M23）与章节结构（M90），**不管概念前置依赖**。

## 1. 职责

对给定目标概念 `c`（可用条目键 / 别名 / 概念名指定）与已装载概念集 `L`，求值三件事并落槽：

1. `closure(c) = {c} ∪ ⋃ closure(p)`，`p ∈ prereqs(c)`（传递闭包）；
2. `missing(c, L) = closure(c) − L`（缺失清单：还差哪些概念）；
3. `readiness(c, L) = (missing(c, L) 为空)`（就绪判定）。

前置关系**不在本模块内写死**，来自概念图资产 `CONCEPT_GRAPH`（图 = 内容，求值 = 机制，I1 三正交分离）。图按**双支**组织（计算与实现栈 / 应用与系统设计栈），分支只用于过滤与呈现；概念别名表让「同一个概念的不同说法」同解。求值器与复现命令见 §7。

## 2. 协议声明（01 §2 模块协议）

```yaml
Module:
  id: AI系统:M25
  name: 前置闭包求值
  layer: P40
  inputs: [M00, M50, intent]
  outputs: [concept_closure, prereq_missing_list, prereq_state]
  events:
    publish: [concept_closure_ready, prereq_missing]
    subscribe: []
  core:
    assets: [CONCEPT_GRAPH]
    logic:
      读图: 取 CONCEPT_GRAPH 机读块 → 节点表 / 前置边 / 分支 / 别名（边自带 provenance，无溯源边拒用）
      解析: 检索词 → 条目键（顺序 条目键 → 别名 → 概念名；别名重复即拒，防歧义）
      展开: closure(target) 迭代展开前置边（DAG 保证终止；有环即拒，按资产 §4 conflict_rules 归并）
      求差: missing(target, L) = closure(target) − L
      落槽: 写 PrereqState{target, closure, missing, readiness, branch, tick}
      发布: closure 收敛 → concept_closure_ready；missing 非空 → prereq_missing
  replaceable: true
```

## 3. 数据槽契约（扩展 M00 数据槽 · 前置依赖域）

```yaml
PrereqState:
  target: string              # 目标概念 id（如 C22）
  closure: [string]           # 前置闭包（含 target 自身，去包含包外前置）
  missing: [string]           # 缺失清单 = closure − 已装载集
  readiness: bool             # missing 为空即就绪
  branch: string              # 目标所属分支（compute / app；呈现与过滤用）
  tick: number                # 求值节拍（来自 通用:M10 节拍，经 M50 调度传入）
```

## 4. 事件契约

| 事件 | 方向 | 载荷 | 说明 |
|---|---|---|---|
| `concept_closure_ready` | publish | `{target: string, closure_size: number, closure: string[]}` | 闭包求值收敛（同一 target 重复求值结果相同，事件可幂等消费） |
| `prereq_missing` | publish | `{target: string, missing_size: number, missing: string[]}` | 缺失非空（就绪门未开）：供装载方按 `load_order` 补齐 |

> 本模块零订阅：求值由调度面（M50 回合推进）与本包 P07 管线层序触发，不起跨包事件依赖。

## 5. 核心逻辑（伪代码）

```
1. 读资产 CONCEPT_GRAPH（assets/，经 asset_get 五接口寻址）→ 节点表 N、边 E、分支 B、别名表 A、外部前置族 X
2. 解析检索词 → target（条目键 / 别名 / 概念名；无解即拒）
3. closure ← {target}；work ← prereqs(target)
4. while work 非空：取 p；若 p ∉ closure：closure ← closure ∪ {p}；work ← work ∪ prereqs(p)
5. missing ← closure − L（L 为已装载概念集，来自 PrereqState 或装配输入）
6. PrereqState ← {target, closure, missing, readiness: missing == ∅, branch, tick}
7. publish concept_closure_ready；if missing ≠ ∅ → publish prereq_missing
```

## 6. 不变式遵守（01 §5）

- I1 三正交分离：只声明**求值能力**，不持顺序（顺序在 P07 管线）与内容（图 = 资产）。
- I2 核心固定：依赖 M00 数据槽与 M50 调度，未替换任何官方核心模块。
- I3 通信契约：仅经 `PrereqState` 与两个事件通信，不直读他包状态。
- I4 数据隔离：零主题材外资产，唯一引用为概念图 `CONCEPT_GRAPH`（本包自带）。
- I5 真相唯一：前置关系唯一真相在 `CONCEPT_GRAPH`；本模块不复制一份边表。

## 7. 引用资产与可复现求值

- 资产键：`CONCEPT_GRAPH`（`assets/CONCEPT_GRAPH.md`，形制：人读表 + 别名表 + 机器可读块三形态同源；v1.1 起双支覆盖 47 概念）。
- 参考求值器（只读、确定性、非门禁）：`scripts/ai_domain_closure.py`。

```
python scripts/ai_domain_closure.py --target C22 --loaded C01,C07,C08,C10,C18
python scripts/ai_domain_closure.py --target RAG --loaded C00,C01,C20,C27   # 别名检索

```
