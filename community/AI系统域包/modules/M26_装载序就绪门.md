# 模块 AI系统:M26 · 装载序与就绪门

> 类别：AI系统｜来源：社区（AI系统域包自带，类内段）｜挂载点：P60 长期演变（active，default）｜依赖：AI系统:M25、M00｜订阅：concept_closure_ready、prereq_missing｜发布：load_order_ready｜状态：active
> 用途：把 AI系统:M25 的闭包结果收口成**对外可消费的两个面**——① 合法装载序（`toposort` 的确定性线性化）；② 逐概念就绪判定与缺失清单投影。它是域包对下游（装配方 / 课程排程 / 前置缺失清单消费者）的出口，**不重复求值**：闭包计算归 AI系统:M25（I1 正交，单点真相）。

```yaml
machine_contract:
  conformance: "L2"
  schema: "1"
  id: AI系统:M26
  name: 装载序与就绪门
  category: AI系统
  layer: P60
  inputs: [AI系统:M25, M00]
  outputs: [load_order, readiness_gate]
  events:
    publish: [load_order_ready]
    subscribe: [concept_closure_ready, prereq_missing]
  interfaces: [load_order_query, readiness_gate_query]
  io_types:
    outputs:
      load_order: untyped
      readiness_gate: untyped
    inputs: {}
```

## 1. 职责

1. 订 `concept_closure_ready` / `prereq_missing`（AI系统:M25 发布）→ 汇入装载序判定；
2. 对概念图求**确定性拓扑序**（`load_order`）：同层并列按概念 id 升序，保证同输入同输出；
3. 维护**就绪门**（`readiness_gate`）：逐概念给 `{ready | blocked_by:[缺失概念]}`，并给出「先补哪个」的下一步；
4. 发布 `load_order_ready`（装载序收敛，可对外装配）。

## 2. 协议声明（01 §2 模块协议）

```yaml
Module:
  id: AI系统:M26
  name: 装载序与就绪门
  layer: P60
  inputs: [AI系统:M25, M00]
  outputs: [load_order, readiness_gate]
  events:
    publish: [load_order_ready]
    subscribe: [concept_closure_ready, prereq_missing]
  core:
    assets: [CONCEPT_GRAPH]
    logic:
      收口: concept_closure_ready → 记 PrereqState.closure 收敛；prereq_missing → 记缺失
      排序: toposort(图) → 线性化（并列按 id 升序；有环拒出并回退 AI系统:M25 的冲突规则）
      判门: 逐概念 readiness = missing 为空；blocked 者给 blocked_by 清单
      发布: 排序与判门就绪 → load_order_ready（幂等：同图同装集结果一致）
  replaceable: true
```

## 3. 数据槽契约（扩展 M00 数据槽 · 装载序域）

```yaml
load_order:
  seq: [string]               # 概念 id 的合法线性化（拓扑序）
  source_graph: string        # 图资产键（CONCEPT_GRAPH）
  layer_hint: {string: string}   # 概念 id → 建议驻留层（P00-P80，来自图节点 layer）
readiness_gate:
  ready: [string]             # 已就绪概念
  blocked: {string: [string]} # 概念 id → 阻断它的缺失概念（缺谁补谁）
```

## 4. 事件联动

- subscribe `concept_closure_ready`（AI系统:M25 发布）：闭包收敛 → 重算装载序与就绪门。
- subscribe `prereq_missing`（AI系统:M25 发布）：缺失非空 → 就绪门标记 `blocked_by`，不外放未就绪序。
- publish `load_order_ready`：装载序收敛 → 下游（装配方 / P07 管线后续层位）可读序与门。

## 5. 核心逻辑（伪代码）

```
1. on concept_closure_ready / prereq_missing → 更新 PrereqState 快照
2. seq ← toposort(图)：入度 0 集按 id 升序取件；每取出即减后继入度（图有环 → 拒出 + 记档）
3. for c in seq: ready(c) ? ready ← ready ∪ {c} : blocked[c] ← missing(c, L)
4. load_order ← {seq, source_graph: CONCEPT_GRAPH, layer_hint: 图节点 layer}
5. publish load_order_ready（同图同装集重复发布内容一致 = 幂等）
```

## 6. 不变式遵守（01 §5）

- I1 三正交分离：只承担**排序与判门**，不持闭包算法（AI系统:M25）与图内容（资产）。
- I2 核心固定：依赖 AI系统:M25 与本包图资产，官方核心 M00/M50 槽位不动。
- I3 通信契约：仅经 `load_order` / `readiness_gate` 与 `load_order_ready` 通信。
- I4 数据隔离：零新增资产，只读 `CONCEPT_GRAPH`（不复制图内容）。
- I5 真相唯一：装载序是**派生量**（由图实时求值），不落第二份手写顺序表。
