> 类别：通用｜来源：通用核心基础包｜挂载点：P40 行为决策（active）｜编号段：M91-M99 社区预留
> 依赖：M50（主循环）、事件:M06（任务剧情）、事件:M13（NPC 交互）——官方核心（R1 core_only）；本包 M93/M94 事件
> 发布：`decision_brief`｜订阅：`quest_state`、`interaction_update`（官方）、`state_snapshot`、`beat_tick`（本包）
> 引用装配：无跨包引用（references=[]，v2 白名单恒空；通用类整包零借阅）
> 对应 protocol.yaml modules[2].id=M95｜模板制作指令包 格式一（八要素）示例落盘

## 1 职责

行为决策层（P40）装配模块：题材无关的决策上下文汇总器。在 M50 主循环的每个决策回合，订阅官方事件层 M06 任务态（`quest_state`）与 M13 NPC 交互态（`interaction_update`）、本包 M93 状态快照（`state_snapshot`）与 M94 统一节拍（`beat_tick`），把回合内全部决策相关上下文汇总为**统一简报** `decision_brief`，交 P80 层 M96 作输出润色对齐基准（领域包 P40 决策模块亦可订阅消费）。本模块只做通用汇总不做题材决策（M50 本体仍驻官方核心调度器，本模块为决策回合的上下文聚合机制增强）。
## 2 输入输出（八要素）
- 编号：M95（社区预留段，protocol.yaml module_id_range 在册）
- 名称：通用决策汇总
- 类别：通用（通用类整包独占类别——R2）
- 层：P40 行为决策（active，mount_layers.P40.default=[M95]）
- 输入（订阅）：quest_state / interaction_update（官方事件层）；state_snapshot / beat_tick（本包 M93/M94）
- 输出（发布）：decision_brief
- 可替换：是（通用装配位；卸载后 P40 回落空决策层，领域包可自带题材决策汇总模块替代）
- 核心逻辑：见 §3
## 3 核心逻辑：三段式决策汇总
```yaml
# 三段式：事件入栈 → 回合聚合 → 简报封装
m95_decision_summary:
  step1_stack:            # 回合事件入栈（M50 决策回合边界内）
    - from 官方: quest_state          # M06 任务态（最新档）
    - from 官方: interaction_update   # M13 NPC 交互态
    - from 本包: state_snapshot       # M93 四域快照
    - from 本包: beat_tick            # M94 统一节拍
  step2_aggregate:        # 回合聚合（按 M50 决策回合对齐）
    rule: |
      同一回合内到达的全部事件 → 去重合并为单份上下文
      跨回合 → 旧回合简报封口，新回合开栈
  step3_brief_pack:       # 简报封装（统一结构，供 P80 输出对齐）
    produce: decision_brief
    payload: { context: [任务, NPC, 状态, 节拍], round: <回合号>, origin: M95, aggregated: true }
```
## 4 事件契约
- subscribe `quest_state`：官方 M06 任务态广播，作为任务面决策上下文
- subscribe `interaction_update`：官方 M13 NPC 交互态广播，作为 NPC 面决策上下文
- subscribe `state_snapshot`：本包 M93 四域快照，作为状态基座上下文
- subscribe `beat_tick`：本包 M94 统一节拍，作为回合时序上下文
- publish `decision_brief`：统一决策简报（携带 context/round），P80 层 M96 与领域包决策模块订阅消费
## 5 资产
本模块无自有资产（assets.count=0）；机制包无题材资产，不借阅任何源包资产（references=[]、cross_package=[]，通用类整包零资产零借阅）
