3. MCP (deepest, needs a local checkout)

A read-only MCP server: retrieval and content access, no write path; unknown URIs and unknown tools are refused. Start it and declare it:

python scripts/nf.py serve

4. Boundaries, stated up front

  • ⚠️ The only official entry point is ninfenz.dev: no paid version, no client to download, and never a request for an account, phone number or payment details. Project content on third-party sites (especially ad-heavy resource / game / download sites) is not affiliated with the project — do not enter information or download files there; see "Official entry and how to spot copies" on the home page.
  • The gates check structure and reproducibility, not prose quality - that boundary is part of the design.
  • No hosted service, no paid tier, no telemetry, no API key: the repository is everything, MIT.
  • Never invent identifiers: if it is not in the registry, say so, leave it blank and state the gap.
  • The npm package (name ninfenz, source under packaging/npm) is prepared but not published yet: npx -y ninfenz doctor starts working after the first release. Until then use path 2.
